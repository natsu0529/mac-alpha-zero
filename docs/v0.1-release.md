# Publishing the v0.1 Othello run

## Select the checkpoint

Use the run that satisfies [#5](https://github.com/natsu0529/mac-alpha-zero/issues/5). Record the training commit, the complete from-scratch command, elapsed training time and self-play game count. Keep its network weights, evaluation log and final Edax match output together. The published model must score **above 0.5** against Edax level 1 over 100 games, with 50 six-ply openings played once per color. Compute the score as `(wins + draws / 2) / 100`.

Record the network shape, simulation count, opening seed, and non-root selection rule from that match. Use the same checkpoint for the following release materials.

| Material | Source and command |
|---|---|
| Training curve | Fit the evaluation log with `benchmarks/checkpoint_elo.py`, then use `benchmarks/plot_strength.py`. Follow the commands under “Results so far” in the README. |
| Game animation | Use `uv run --group media python benchmarks/othello_gif.py record WEIGHTS moves.json --level 1` with the winning model's shape and search settings, then `uv run --group media python benchmarks/othello_gif.py render moves.json game.gif`. Check the final disc counts before choosing the recorded game. |
| Published weights | Copy the selected network's `.safetensors` file to the release staging directory as `othello.safetensors`. Compute `shasum -a 256 othello.safetensors` there and include the checksum in the release notes. |

The game record includes the checkpoint SHA-256. Match it against the staged weights. If the qualifying search uses the improved non-root rule, pass `--improved-nonroot` to both the recorder and the match command.

## Prepare and verify the GitHub release

1. Add the qualifying run and its reproduction command to ROADMAP.md. Update the README with its curve, winning GIF, hardware, and download and evaluation commands. Record the result as wins, draws, losses and score. The historical baseline remains useful for comparison.
2. Bump the project version to 0.1.0 with `uv version 0.1.0`, update the lockfile, and merge the release changes after CI passes. Tag that merged commit `v0.1.0`.
3. Draft the GitHub release for the existing tag. Attach **othello.safetensors**. Keep the replay buffer, optimizer, Edax binary, and Edax data out of the assets. The notes should give the exact model shape, search options, SHA-256, result, hardware, training command, and the relative path to the curve.
4. From a fresh clone, check out `v0.1.0` and download the draft asset as a maintainer. Build Edax with `scripts/build_edax.sh`. Verify the checksum and reproduce the published score with the release's exact options. Publish the draft once those checks pass.

The README download example can use the following commands once the asset is available. Fill in the verified match options from the release, including the number of simulations, channels and blocks.

```sh
mkdir -p checkpoints/v0.1.0
gh release download v0.1.0 --pattern othello.safetensors --dir checkpoints/v0.1.0
shasum -a 256 checkpoints/v0.1.0/othello.safetensors
```

Use `benchmarks/edax_match.py --search-only --levels 1 --games 100` with `--checkpoint checkpoints/v0.1.0/othello.safetensors`. Readers can also pass that file to `examples/play_othello.py` to play in the terminal.

## Publish the wheel

For the first PyPI release, configure a [pending trusted publisher](https://docs.pypi.org/trusted-publishers/creating-a-project-through-oidc/) for project `mac-alpha-zero`, GitHub owner `natsu0529`, repo `mac-alpha-zero`, workflow `publish.yml`, and environment `pypi`. Once the GitHub release is public, dispatch the workflow from main:

```sh
gh workflow run publish.yml --ref main -f tag=v0.1.0
```

After publication, run `uv init` and `uv add mac-alpha-zero==0.1.0` in an empty directory on Apple Silicon, then import `mac_alpha_zero`. Add the installation command to the README once it succeeds.
